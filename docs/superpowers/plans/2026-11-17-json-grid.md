# JSON Grid Implementation Plan

> **For agentic workers:** Use subagent-driven-development for task-scoped implementation and review. Steps use checkbox syntax for tracking.

**Goal:** Deliver and publish an MIT-licensed DBX JSON workbench with synchronized source, nested editable grids and editable trees.

**Architecture:** One lossless JSON document is the authority. UI state stores paths into that document; filters and sorting never change identity. DBX Host APIs are behind a capability-checked adapter with a browser preview fallback.

**Tech Stack:** React, TypeScript, Vite, CodeMirror, lossless-json, Vitest, DBX plugin CLI 0.1.10.

**Spec:** `docs/superpowers/specs/2026-11-17-json-grid-design.md` (approved 2026-11-17; user also authorized public GitHub/MIT/release/store submission).

## Global Constraints

- Local JSON processing only; no external network origin permission and no native sidecar.
- Plugin `io.github.ryn-mic.json-grid`, publisher `ryn-mic`, version `0.1.0`.
- All UI dependencies bundled; Vite `base: './'`; `ui/index.html` is the package entry.
- Preserve numeric lexemes and JSON types; reject duplicate object keys with a visible error.
- Preserve original array indices after search, filter and sort.
- Invalid source is retained; stale structured data cannot be edited or exported as if current.
- Limit input to 10 MiB UTF-8, nesting to 256, visible expand-all to 5000 nodes; paginate grids.
- Host storage: 256 KiB/value and 1 MiB total; drafts opt in and bounded across instances.
- MIT license, public source, immutable release candidates with hashes, and store PR registration.

## File boundaries

- `src/core/json.ts`: pure JSON types, parsing, paths and immutable editing.
- `src/core/grid.ts`: pure shape-to-row conversion, matching and sort helpers.
- `src/components/TreeView.tsx`, `GridView.tsx`, `InlineValue.tsx`: data views only.
- `src/host/bridge.ts`: DBX capability adaptation, file and clipboard operations.
- `src/useDocument.ts`: one shared history for raw and structured edits.
- `src/App.tsx`: application commands, selection, editor, dialogs and status.
- `src/styles.css`: Host token based theme, responsive dense workbench layout.
- `scripts/`: build/contract/release metadata checks; `.github/workflows/`: CI and release.

### Task 1: Lossless data layer

**Files:** Create `src/core/json.ts`, `src/core/grid.ts`, `tests/json.test.ts`, `tests/grid.test.ts`.

**Interfaces:** `JsonValue`, `JsonPath = (string | number)[]`; `parseJson(text): JsonValue`, `stringifyJson(value, indent?: number): string`, `typeOf(value): string`, `getAt(value,path)`, `setAt(value,path,next)`, `removeAt(value,path)`, `insertAt(value,parent,key,next)`, `renameAt(value,path,key)`, `formatPath(path)`, `pathKey(path)`, `childrenOf(value,path)`, `preview(value)`, `findMatches(value,query): JsonPath[]`. Grid exports `gridModel(value,path): { columns: string[], rows: GridRow[] }`, each row carries original `path` and cells `{key,path,value,missing}`. Export `matchesText(value,query)` and comparison helper if useful.

- [ ] Write contract tests first for exact large numeric lexemes, duplicate keys, special keys, empty structures, immutable edits and filtered/sorted path identity. For example: `expect(stringifyJson(parseJson('{"id":9007199254740993}'))).toContain('9007199254740993')`.
- [ ] Run `npx vitest run tests/json.test.ts tests/grid.test.ts` and confirm missing implementation fails.
- [ ] Implement the pure layer with lossless-json; read its installed types/docs for duplicate-key callback and parse-number semantics. Restrict depth and UTF-8 bytes before recursive operations.
- [ ] Run the same targeted suite, inspect results, commit only task files.
- [ ] Obtain spec and quality review using a task diff and test evidence; resolve defects before depending on the API.

### Task 2: Views, document history and Host workbench

**Files:** Create components, bridge, document hook, App, styles, main entry and UI/Host tests; update manifest and build configuration.

**Interfaces:** Core consumes Task 1 API. Shared view props: `{ value: JsonValue; path: JsonPath; selected: JsonPath; onSelect(path): void; onEdit(path): void; onAction(action, path): void; query: string; filter: boolean; expansion: 'default'|'all'|'none'|number; expansionVersion: number; disabled: boolean; locale: 'zh-CN'|'en'; }`. `action` is `'copy-path'|'copy-value'|'add'|'rename'|'delete'`. Callbacks open application dialogs; component-owned row editors may call `onEdit` for typed commit. Props may add a `matches`/`activeMatch` path if needed and must stay synchronized in `src/components/types.ts`.

- [ ] Build a dense two-pane workbench: source editor on left, grid/tree tabs right, selected-path breadcrumb and contextual inspector. Use local sans/mono fonts with DBX tokens, teal active states, type colors and restrained animations.
- [ ] Implement lazy expansion, recursive nested grid cells, grid pagination, missing-cell markers, column filtering/sort and tree keyboard navigation; selection retains original paths.
- [ ] Implement typed edit dialog (string/number/boolean/null/object/array), add/rename/delete, and source validation. A shared history stores raw strings with 100-state/20 MiB combined cap; structured edits serialize only valid documents.
- [ ] Connect `ready`, env changes, capabilities, Host copy, clipboard read, file pick/read/save/cancel/drop and opt-in bounded draft storage. Standalone browser fallback uses ordinary file input/download and clipboard only outside Host.
- [ ] Implement search counts/navigation, filter ancestors, format/minify, parse/stringify JSON string, import/export, source maximize, adjustable split, expand/collapse/depth, undo/redo.
- [ ] Write meaningful tests for typed edits, stale edit rejection, synchronized undo, Host capability denial/cancel, path-copy and source-to-view flow. Run `npm test` and `npm run build`.
- [ ] Exercise the actual DBX dev-host sandbox in a browser (copy/file API, themes/locales, repeated contexts) and save an acceptance record with precise limits.
- [ ] Obtain task review and fix important defects.
