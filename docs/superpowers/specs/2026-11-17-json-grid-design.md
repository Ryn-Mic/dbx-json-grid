建议开发一个独立的纯前端 DBX 工作台插件。默认展示可编辑嵌套网格，同时提供 DevTools 风格的树形视图。

## A 方案选择

| 方案 | 优点 | 代价 | 建议 |
|---|---|---|---|
| 纯前端，自建网格与树形交互 | 可以统一路径、编辑、搜索和撤销 | 需要实现结构化编辑交互 | 推荐 |
| 纯前端，组合现成 JSON 编辑器 | 树形基础能力开发较快 | 网格与树形的状态、交互需要适配 | 备选 |
| 前端加原生 Sidecar | 后续适合超大文件和磁盘缓存 | 首版增加多平台构建与进程管理 | 后续按需求评估 |

建议采用 React、TypeScript 和 Vite。源码区采用 CodeMirror；依赖与字体随安装包提供。

这份方案复刻 JsonGrid 的核心交互，并扩展可编辑树形视图。所有 JSON 处理都在本地完成。

## B 工作台布局

顶部工具栏提供打开文件、粘贴、格式化、压缩、撤销、重做和导出。

主区域默认左右分栏，分隔线可拖动。左侧是 JSON 源码，右侧切换网格与树形视图。两侧都能单独最大化。

右侧工具栏提供搜索、筛选、展开和折叠。底部显示当前路径、值类型、解析状态和筛选结果数量。

| 视图 | 主要用途 | 编辑方式 |
|---|---|---|
| 源码 | 输入、粘贴、格式化和校验 | 文本编辑，显示错误行列 |
| 网格 | 比较同一数组里的多条记录 | 双击单元格，提交后同步源码 |
| 树形 | 浏览任意层级，定位单个字段 | 双击值，菜单管理字段与数组项 |

## C 网格转换规则

| JSON 结构 | 展示规则 |
|---|---|
| 对象数组 | 一项一行，所有字段的并集作为列 |
| 普通对象 | 字段与值两列 |
| 基础值数组 | 原始下标与值两列 |
| 混合数组 | 原始下标、类型与值三列 |
| 嵌套对象或数组 | 单元格内展开子网格，也可进入该节点 |
| 根节点基础值 | 类型与值，仍可编辑 |
| 缺失字段 | 使用缺失标记，与 null 区分 |
| 空对象和空数组 | 保留类型与数量信息 |

默认保留层级结构，避免把深层字段全部摊平成列。表头固定，支持列宽调整和稳定排序。

排序与筛选只改变展示顺序。编辑和路径复制始终指向原始数据位置。

## D 树形与常用 JSON 操作

| 功能 | 首版行为 |
|---|---|
| 树形预览 | 缩进、三角展开按钮、类型配色、对象摘要与数组长度 |
| 行内编辑 | 双击编辑；Enter 提交，Esc 取消 |
| 类型控制 | 字符串、数字、布尔值、null 显式区分 |
| 结构编辑 | 新增字段、重命名字段、删除节点、插入数组项 |
| 对象编辑 | 支持编辑整个子树，并在提交前校验 |
| 复制 | 复制 JSONPath、键、值、当前子树 JSON |
| 搜索 | 搜索键和值，显示命中数，支持上一个与下一个 |
| 搜索定位 | 展开命中项的祖先节点，并滚动到节点 |
| 树形筛选 | 只显示匹配项及其祖先，清除后恢复 |
| 网格筛选 | 按列筛选，支持包含、等于和数值比较 |
| 展开折叠 | 当前节点、当前子树和全部；支持指定展开深度 |
| 文件处理 | 打开、拖入、导出完整 JSON，导出当前子树 |
| 文本工具 | 格式化、压缩、校验、解析 JSON 字符串、转为 JSON 字符串 |
| 历史 | 源码、树形和网格共用撤销与重做 |
| 键盘 | 树形方向键导航、查找快捷键、编辑与取消快捷键 |

JSONPath 示例：`$.users[0].address.city`。含点号或空格的键使用括号引用。经过筛选后，下标仍指向原数组位置。

搜索模式高亮所有匹配节点。筛选模式隐藏不匹配内容，并明确显示筛选状态。

## E 编辑一致性与数据边界

```flow LR
源码输入 -> 解析与校验
解析与校验 -> 文档状态: 有效输入
文档状态 -> 网格视图
文档状态 -> 树形视图
网格视图 -> 编辑事务
树形视图 -> 编辑事务
编辑事务 -> 文档状态: 原子提交与撤销记录
文档状态 -> 源码同步
```

JSON 无效时保留原始输入，并提示错误位置。右侧若保留上次结果，必须标明已过期，并暂停结构化编辑。

数字处理需保留超出 JavaScript 安全整数范围的原始字面量。格式化、编辑其他字段和导出均不得悄悄改变大整数。

字符串必须保留 Unicode 和转义语义。含特殊字符的键、空键及 `__proto__` 键均按普通数据处理。

重命名遇到同名字段时拒绝覆盖。重复键的原始 JSON 需明确提示，避免静默丢失字段。

树形采用按需展开和可见行渲染。大型数组分页，全部展开设置节点数量上限，并给出提示。

大文件解析设置明确的大小和深度边界。具体上限通过开发时的性能测量确定，不宣称支持无限大小。

## F DBX 适配

| 接入点 | 设计 |
|---|---|
| 插件形态 | 纯前端 workbench，产出 universal `.dbxp` |
| 初始化 | 等待 `window.dbxPlugin.ready`，读取主题和语言 |
| 复制 | 使用 `dbxPlugin.copy`，按能力检查结果展示入口 |
| 粘贴按钮 | 能力可用时读取剪贴板；失败时保留键盘粘贴 |
| 文件 | 使用 Host 文件传输 API，处理取消与失败 |
| 明暗主题 | 使用 DBX 主题 tokens，并响应环境变化 |
| 语言 | 首版支持简体中文与英文 |
| 状态保存 | 保存布局、选项及用户主动启用的小草稿 |
| 隔离 | 不同工作台实例的输入与编辑历史相互独立 |
| 运行资源 | 使用包内静态资源及相对路径 |

首版建议声明 `host.storage` 和 `host.clipboard:read`。其余权限仅在实际使用时增加。

DBX 文档规定：单个状态值最多 256 KiB，状态存储总量最多 1 MiB。大 JSON 通过文件导出保存；超限草稿必须提示未保存。

源码输入默认留在当前会话。草稿恢复需要用户主动开启，并提供清除入口。

后续可增加查询结果视图入口。官方 `result-view` 传入有行数限制的结果快照，此项独立验收。
